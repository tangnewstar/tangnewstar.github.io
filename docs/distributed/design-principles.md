# 分布式系统思考

传统的单体项目，是一个大的系统包含很多子模块（例如OA系统用户模块，权限模块，财务模块，请假模块）。业务规模扩大和复杂度提高，分布式系统出现来解决这个问题。**将一个大型的单体系统，拆分成n个独立子系统分别部署实例**。用服务实例的调用取代了单体服务内的模块调用。

会有一系列的问题解决：

- 服务之间调用怎么确定目标服务的地址？微服务上线下线怎么让调用方感知？（配置？编码？还是其他）
- 分布式服务通常是多节点实例，怎么让流量负载均衡？（k8s ingress or nginx?或是引入外部lb组件）
- 分布式环境下，调用失败怎么重试？节点故障集群怎么容错？
- 流量按版本、分组路由、灰度发布、限流熔断怎么支持？
- 服务调用的监控和统计（次数、RT、成功率）
- 分布式系统足够庞大后，怎么支持多协议（Http，RPC，UDP）和多语言？

为了解决上述问题，分布式服务框架应运而生。

目前比较普及的分布式系统框架有：SpringCloud 和 **Dubbo**
