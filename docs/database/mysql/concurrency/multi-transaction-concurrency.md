# 多事务并发

### 多事务并发问题

我们知道在并发情况下和单线程处理问题的方式是不一样的，MySQL 服务器支持多个 Client 进行连接，意味着存在多事务并发情况，同样在多事务并发情况下是存在脏读（dirty read）、不可重复读（non-repeatable read）、幻读（phantom read）的问题。

- **脏读**：事务 A 读取到事务 B 未提交的修改，若 B 回滚，A 读取的数据无效
- **不可重复读**：事务 A 两次读取同一数据，期间事务 B 修改并提交了该数据，导致 A 两次结果不同
- **幻读**：事务 A 两次查询同一范围的数据，期间事务 B 插入 / 删除了符合条件的新数据，导致 A 两次结果的行数不同

小结一下：

- 脏读：读到其他事务未提交的数据
- 不可重复读：前后两次读取的数据不一致
- 幻读：前后读取的记录数量不一致

!!! note "提示"
    mysql 事务的隔离级别由低到高：

    Read Committed → Read Committed → Repeatable Read → Serializable

    MVCC 机制：

    - RC 级别每次 select 都会创建 ReadView，只能读取已提交的事务。也意味着多次读取到不同的结果。（当前读）
    - RR 级别在事务开始时创建 ReadView 然后整个事务内沿用（快照读），保证了多次读取的一致性。同时使用临键锁，防止修改或插入读取范围数据，保证了当前读的一致性。

        但是，快照读和当前读混用会导致幻读。

    - Serializable 级别全表级别的读锁（S 锁）和写锁（X 锁）互斥。

### 不同的事务隔离级别

既然多事务并发情况下会出现脏读、不可重复读、幻读的情况，那么这些该如何避免呢？不同的事务隔离级别在并发事务下也会产生不同的问题：

- **Read Uncommitted**
    - 最低隔离级别，一个事务可以读取另一个未提交事务的修改
    - 问题：存在**脏读**（读取到未提交的无效数据）、不可重复读、幻读
- **Read Committed**
    - 一个事务只能读取另一个已提交事务的修改
    - 避免**脏读**，但仍可能出现**不可重复读**（同一事务中多次读取同一数据，结果因其他事务提交而不同）和**幻读**
- **Repeatable Read（默认）**
    - 同一事务中，多次读取同一范围的数据，结果始终一致（不受其他事务提交的修改影响）
    - 避免**脏读**和**不可重复读**，通过 InnoDB 的 **Next-Key Lock**（行锁 + 间隙锁）机制，可有效避免**幻读**
- **Serializable**
    - 最高隔离级别，强制所有事务串行执行（类似单线程），完全禁止并发操作；全表级别的读锁（S 锁）和写锁（X 锁）互斥
    - 解决：避免所有并发问题（脏读、不可重复读、幻读），但并发性能极差
