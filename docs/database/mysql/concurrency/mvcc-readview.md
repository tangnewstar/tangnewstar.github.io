# MVCC & ReadView

MySQL 的 **MVCC（Multi-Version Concurrency Control，多版本并发控制）** 是 InnoDB 引擎实现高并发读写的核心机制，它通过保存数据的多个历史版本，允许读写操作并行执行（读不阻塞写，写不阻塞读），同时保证事务隔离性。

为了平衡并发读写性能，InnoDB 提供两种读操作模式：**快照读（Snapshot Read）** 与 **当前读（Current Read）**。它们的核心区别在于是否读取数据的最新版本，以及是否会加锁：快照读是 MVCC 在非阻塞读上的具体实现，当前读则是加锁读（悲观锁）的实现。

## MVCC 核心原理

MVCC 的本质是 **"数据多版本快照"**，核心思想是：

- 事务对数据的修改不会直接覆盖旧数据，而是生成一个新的版本，并保留旧版本（通过 `undo log` 实现）
- 不同事务根据自身的隔离级别，只能看到符合条件的历史版本或最新版本，从而避免读写冲突

### 关键组成部分

1. **隐藏列**：InnoDB 为每行数据添加了三个隐藏列，用于版本管理：
    - `DB_TRX_ID`：记录最后一次修改该数据的事务 ID（创建版本）
    - `DB_ROLL_PTR`：指向该数据的历史版本（存储在 `undo log` 中），形成版本链
    - `DB_ROW_ID`：自增 ID（若表无主键时使用）
2. **undo log**：保存数据的历史版本，用于事务回滚和 MVCC 快照读取。当数据被修改时，旧版本会被写入 `undo log`，并通过 `DB_ROLL_PTR` 链接
3. **Read View（读视图）**：事务启动时生成的 "快照视图"，包含当前活跃事务的 ID 列表，用于判断某个版本的数据是否对当前事务可见
    - 规则：若数据的 `DB_TRX_ID`（修改事务 ID）小于 Read View 中的最小活跃 ID，或属于已提交事务，则该版本可见

## 快照读（Snapshot Read）

快照读是指**读取数据的历史版本（快照）**，而非数据库当前最新版本。它基于 MVCC 实现，**不加锁**，因此不会阻塞其他事务的读写操作，是提高并发性能的关键。

**实现原理**

1. **数据多版本**：InnoDB 通过 `undo log` 保存数据的历史版本（修改前的状态）
2. **Read View（读视图）**：事务启动时生成一个 Read View，记录当前活跃的事务 ID，用于判断哪些版本的数据对当前事务可见
    - 在 `Read Committed` 隔离级别下：每次 `SELECT` 都会生成新的 Read View，因此只能看到已提交的最新版本（避免脏读）
    - 在 `Repeatable Read` 隔离级别下：整个事务只生成一次 Read View，因此多次查询能看到相同的快照（实现 "可重复读"）

快照读通过 Read View 从数据的版本链中筛选出 "当前事务可见的历史版本"，实现无锁读取。

**特点**

- 不加锁，读写不冲突，并发性能高
- 可能读取的不是最新数据（是历史快照）

## 当前读（Current Read）

当前读是指**读取数据的最新版本**，并且会对读取的记录加锁，阻塞其他事务的写操作（避免脏写）。

```sql
-- 加锁的SELECT语句
SELECT * FROM table WHERE ... FOR UPDATE;  -- 加排他锁（X锁）
SELECT * FROM table WHERE ... LOCK IN SHARE MODE;  -- 加共享锁（S锁）

-- 写操作（隐含当前读，需先读取最新数据再修改）
INSERT、UPDATE、DELETE
```

**实现原理**

1. 读取数据时，直接获取当前最新版本，而非历史快照
2. 对读取的记录加锁（具体锁类型取决于操作）：
    - `FOR UPDATE` 加排他锁（X 锁）：其他事务不能加 S 锁或 X 锁
    - `LOCK IN SHARE MODE` 加共享锁（S 锁）：其他事务可以加 S 锁，但不能加 X 锁
    - 写操作（`UPDATE` 等）会自动加排他锁，确保修改的是最新数据，且不会被其他事务干扰

## MVCC、快照读与当前读的关系

> - MVCC 多版本并发控制只是一个概念，并非具体实现
> - MySQL 实现 MVCC 概念中，快照读就是 MySQL 为我们实现 MVCC 理想模型的其中一个具体非阻塞读功能。而相对而言，当前读就是悲观锁的具体功能实现
> - MVCC 模型在 MySQL 中的具体实现则是由三个隐式字段、undo 日志、Read View 等去完成的
