# Context Switch

### What is Context Switch

再操作系统中，上下文切换Context Switch是指 CPU从一个进程/线程切换到另一个进程（或线程），需要**保存当前线程状态并加载目标线程状态**的过程。

简单来说，每个进程（或线程）再运行时依赖一些环境信息（CPU寄存器值，程序计数器，内存地址空间等）这些就是”上下文”。

当CPU切换到其他线程时，需要保存当前线程的上下文（以便后续恢复），再加载新线程的上下文，这个过程就是上下文切换。

上下文切换的场景：

- **线程（进程）调度**：操作系统为了保证多线程并发（如CPU时间片用完，高优先级线程占用），主动切换线程
- **中断处理**：硬件（磁盘，网卡）或软件触发中断时，CPU暂停当前线程，转取执行中断服务程序
- **系统调用**：线程执行需要内核介入的操作（如文件读写）时，会从用户态切换到内核态

### 上下文切换的开销

- 时间开销：保存和加载上下文需要执行一系列指令，占用CPU时钟周期
- 缓存失效：每个进程的内存访问模式不同，切换后CPU缓存（如L1，L2）中的数据可能失效，导致后续内存访问变慢
- 内核开销：切换过程由内核完成，会占用内核态CPU时间，减少用户进程CPU资源

如果系统上下文切换过于频繁（大量线程竞争CPU时间，频繁中断），会导致CPU大部分时间用于切换而非执行用户任务，性能下降明显

### 如何减少上下文切换开销

思路：减少不必要的切换，或降低单次切换的成本

1. 减少线程数量，避免过度并发

线程数不应该超出CPU核心数太多，例如CPU核心数为8线程控制在10到15比较合理。过多反而导致频繁切换，降低效率。通常会使用线程池复用线程（ThreadPoolTaskExecutor）

1. 使用轻量级线程（协程）

传统线程切换由操作系统内核控制（内核切换），而协程（goroutine）由用户态控制切换，无需进入内核态，切换成本低。适用于：IO密集型任务（网络请求，文件读写），可避免因IO阻塞而导致的频繁上下文切换。

1. 避免频繁的系统调用和中断

系统调用会触发由用户态到内核态的切换，因尽量批处理操作（例如多个小文件合并为一次大写入）。避免不必要的IO操作（写日志文件），降低中断概率。

1. 优化锁竞争

多线程竞争共享资源时，锁（互斥锁）会导致线程阻塞和唤醒，触发上下文切换。

优化方法：细粒度锁，使用无锁数据结构（原子操作），避免长时间持有锁

所以**对于任务耗时短的情况，要求线程尽量少**，如果线程太多，有可能出现线程切换和管理的时间，大于任务执行的时间，那效率就低了；

**对于耗时长的任务，要分是CPU任务，还是IO等类型的任务**。如果是CPU类型的任务，线程数不宜太多；但是如果是IO类型的任务，线程多一些更好，可以更充分利用CPU。

**高并发，低耗时的情况**：建议少线程，只要满足并发即可，**因为上下文切换本来就多，并且高并发就意味着CPU是处于繁忙状态的， 增加更多地线程也不会让线程得到执行时间片，反而会增加线程切换的开销**；例如并发100，线程池可能设置为10就可以；

**低并发，高耗时的情况**：建议多线程，保证有空闲线程，接受新的任务；例如并发10，线程池可能就要设置为20；

**高并发高耗时**：1. 要分析任务类型；2. 增加排队；3. 加大线程数
