# JVM内存布局及垃圾回收机制

#### 内存布局

- JVM Heap：**线程共享**的区域，运行时用来**存放对象实例和数组**。

<aside>
💡

GC垃圾回收工作的主要区域，在分代垃圾回收算法中分为新生代（Eden，2 Survivor）和老年代

</aside>

- Method Area：**线程共享**的区域，用于存储**类信息，常量，静态变量，JIT编译代码**等。

<aside>
💡

JDK8之前：**永久代来实现**

JDK8之后：**MetaSpace来实现**（MetaSpace使用的是本地内存不受堆内存限制，所以减少了OOM的概率，注：永久代实现是在堆区）

</aside>

- JVM Stack：**线程私有**的区域，用于**存放线程执行的局部变量，操作数栈，动态链接，方法出口**等。

<aside>
💡

调用方法时创建StackFrame进行栈帧入栈，返回方法时栈帧出栈。

异常：当栈深度超过一定值之后会抛出**StackOverFlowError**（栈深度由栈容量-Xss和方法栈帧大小决定）

</aside>

- JVM Native Stack：本地方法栈，用于执行Native本地方法。在HotSpot虚拟机中和JVM Stack在一起。
- Program Counter：程序计数器（**线程私有**），记录当前执行字节码指令的内存地址。唯一不会OOM

#### 垃圾回收

垃圾判断：引用计数法；可达性分析（GC ROOTS)

垃圾回收算法：

- 复制算法：将内存分为两块，只使用一块，GC时将存活对象赋值到另一块，清空当前。**新生代**
- 标记-清除（会存在内存碎片）：先标记可回收对象，再统一清除。**CMS**
- 标记-整理：先标记存活对象向一端移动，然后清理边界外内存。**老年代**

<aside>
💡

CMS：STW两次（初始标记，最终标记）

G1：STW三次（初始标记，最终标记，筛选回收）

</aside>

G1适合回收大堆：

- 传统的GC需要扫描全堆，而G1只需要**扫描部分Region进行增量回收**；
- 引入**HumongousRegion专门存储大对象**，避免大对象直接占用老年代减少FullGC频率
- **youngGC和mixedGC**结合，是的对象晋升更平滑（新生代动态扩容）

ZGC适合超大堆：

- **STW时间与堆大小完全解耦：**
- 染色指针：通过指针判断GC元数据（而不是对象头）
- 读屏障：拦截对象访问，动态修正指向已转移对象的引用
- 全程并发：并发转移对象也不需要STW
