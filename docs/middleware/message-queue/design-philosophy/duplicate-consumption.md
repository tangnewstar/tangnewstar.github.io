# MQ → 工程场景 → 消息重复消费

#### Consumer Offset 机制

可以通过记录已消费的偏移量来确保消息不会被重复消费。

每个consumer group都会维护自己消费到的offset，并定期提交到broker。

如果consumer重启或者发生rebalance，新的consumer会从上次提交的offset继续消费，避免重复消费消息。

#### 消费端幂等

在某些场景下（比如提交offset失败, 或者已消费还未提交重启服务），仍可能发生重复消费的情况，因此需要在消费端进行幂等性处理。

- 数据库层面可以通过**唯一索引或主键约束**来**防止重复数据**写入。例如，对于订单系统，可以使用订单号作为唯一标识，重复写入会被数据库自动拒绝。
- 业务层面可以通过维护一个**消息ID的分布式缓存**，在消费前先查询该消息是否已被处理过。
- 对于特定业务场景，可以通过业务字段的**状态机约束**来保证幂等性，比如订单状态从"未支付"到"已支付"的转换只能发生一次。
